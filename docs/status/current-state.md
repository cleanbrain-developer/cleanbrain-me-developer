## Known constraints

- No backend, database, authentication, or CMS in V1 (see `docs/product/scope.md`).
- There is no mock/simulation UI on this site anymore (ADR-0005) — do not reintroduce a synthetic "generate an event" affordance without a new ADR explicitly reopening that question. The `relayhub-java` integration must stay `GET`-only and CORS-scoped to already-public endpoints; arbitrary URL, header, script, or credential input from a visitor must never be implemented (see `.ai/constitution/engineering-principles.md`).
- Target cluster is 2 vCPU / 4 GB RAM / 40 GB disk (per `cleanbrain-me-infra`) — the combined resource budget across all services already approaches this ceiling (see that repository's README and `cleanbrain-me-entrance`'s own `current-state.md`), so this app must stay lightweight.
- This repository owns application source, Dockerfile, and CI; `cleanbrain-me-infra` owns the production Kubernetes manifest — the two must not duplicate each other's content. Anything that looks like a required infra change is recorded in `docs/infra-required-changes.md`, never implemented here.
- No real chronological work-history timeline (company names, role titles, dates) exists anywhere on the site, by the maintainer's explicit choice — Experience/Resume are focus-area narratives only. Revisit only if the maintainer explicitly asks for a timeline later.
- Case studies are intentionally composite/abstracted with no real metrics — do not "fill in" numbers later without the maintainer explicitly providing real, disclosable ones.
- The application is a static export with no server runtime (ADR-0003) — any future feature needing genuine server-side logic (an API route, middleware, per-request server rendering) requires revisiting that ADR first, not just adding the feature.
- `LiveDashboard` creates a real runtime dependency on `relayhub-java`'s specific API/metric shape (field names in `/api/deliveries/summary` and `/api/targets`, the PromQL metric names `relayhub_ingress_events_total`/`relayhub_delivery_attempts_total`) — see ADR-0004. A breaking change to that API made without awareness of this dependency will silently break the dashboard (it degrades to an error/retry state, not a crash, but the coupling is real). It also polls every 10 seconds per open tab with no caching or rate limiting on this repository's side — fine at current traffic, worth remembering if that ever changes.
- `/` is a client-side-only redirect to `/lab/relayhub` (ADR-0003's static-export constraint) — a crawler or no-JS client sees `<head>` metadata for the site but not the interactive body. The full portfolio narrative previously at `/` now lives at `/profile`, linked from the header logo. There is no offline-safe fallback anymore if `relayhub-java` is down — a deliberate trade-off (see ADR-0005).
- `vitest` is pinned to `^3.2.7`, not latest, due to a real Node 20.11.1 incompatibility in `vitest@5`'s toolchain (see "Deployment prep" above) — do not bump it to `^5` without first confirming the runtime Node version supports it.
- ~~The GitHub Spec Kit CLI (`specify-cli==1.0.8`...) is not actually installed in this repository~~ **Resolved 2026-09-20**: a real Python 3.12 + `uv` + `specify-cli==1.0.8` toolchain is now installed, and `specify init`/`specify integration install codex` were actually run in this repository (see "Completed" above). `.specify/templates/`, `.specify/scripts/`, `.specify/workflows/`, `.specify/integrations/`, and real `.claude/skills/speckit-*/SKILL.md` / `.agents/skills/speckit-*/SKILL.md` files now exist, CLI-rendered rather than hand-written or absent. `.specify/memory/constitution.md` remains the same hand-written, project-authored file it was before (verified unchanged by `md5sum`) — Spec Kit's own manifest tracking correctly treated it as already-customized rather than overwriting it with the generic placeholder template.
